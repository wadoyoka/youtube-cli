# SSH で Mac に入ってログインし直す

`setup` を済ませた Mac に、スマホ（Termius など）や別の PC から SSH で入り、切れたログインを更新する手順。公開ステータスが「テスト」なので、ログインは 7日で切れる（[setup.md](../setup.md)）。

GCP のプロジェクトも、取り込んだ client_secret の JSON も、そのまま使う。設定ディレクトリ（`~/.config/youtube-cli`）と鍵の置き場所（OS のキーチェーン）も変えない。

## 前提

- 今入っている youtube-cli に、Mac の画面でキーチェーンの「常に許可」を押してあること。SSH の中では確認のダイアログを出せないので、まだなら先に Mac の画面で `youtube-cli status` を実行して許可する（[setup.md](../setup.md#鍵の置き場所)）。youtube-cli を入れ直したあとは、もう一度許可が要る。
- ログインする Google アカウントが、OAuth 同意画面のテストユーザーに入っていること。

## 手順

### 1. キーチェーンのロックを外す

SSH のセッションからは、ロックされたログインキーチェーンを読めない。読もうとすると「キーチェーンの確認ダイアログを出せません」で止まる。

```bash
security unlock-keychain ~/Library/Keychains/login.keychain-db
```

Mac のログインパスワードを聞かれるので入力する。

- `-p` でパスワードを渡さない。シェルの履歴やプロセスの一覧に残る。
- Termius のスニペットや履歴の同期にパスワードを保存しない。
- Mac の画面でログインしていて、ロックが既に外れていれば、この手順は要らない。
- ロックを外すと、自分のユーザーで動くプログラムがキーチェーンの項目を読める。ただし項目ごとの ACL は効いたままで、youtube-cli の鍵は youtube-cli だけが読める。SSH のアカウントが乗っ取られている心配があるなら外さない。

### 2. 状態を確かめる

```bash
youtube-cli status
```

ログインが切れていれば、`youtube-cli login` を求めて終了コード 3 で止まる。「キーチェーンの確認ダイアログを出せません」と出たら、[うまくいかないとき](#うまくいかないとき)を見る。

### 3. ログインし直す

```bash
youtube-cli login --no-browser
```

取り込み済みの JSON を使うので、`--client-secret` は要らない。

1. CLI がログイン用の URL を表示する。コピーして、スマホのブラウザで開く。
2. テストユーザーに入れた Google アカウントでログインする。「Google はこのアプリを確認していません」と出たら「続行」で進む。
3. ブラウザは `http://127.0.0.1:<ポート>/?...` に移り、「接続できません」と表示される。これは想定どおり。
4. アドレスバーをタップして、URL を丸ごとコピーする。`code=` と `state=` が含まれていることを確かめる。
5. SSH の端末に貼り付けて Enter を押す。

- 5分以内に貼り付ける。過ぎると「時間切れです」で止まるので、`login` からやり直す。
- **他人から渡された URL は貼り付けない。** 自分でログインして、自分でアドレスバーからコピーした URL だけを貼る（[headless.md](../headless.md)）。
- 待ち受けのポートは毎回ランダムに決まるので、`ssh -L` でポートを転送する方法は使いにくい。貼り付けで済ませる。

### 4. 確かめる

```bash
youtube-cli status
```

ログインしたチャンネルが表示されれば終わり。

### 5. ロックし直す

使い終わったら、キーチェーンをロックし直す。

```bash
security lock-keychain ~/Library/Keychains/login.keychain-db
```

- ログインした状態（`token.enc`）は残る。次に SSH から使うときは、手順 1 でロックを外すだけでよい（ログインし直す必要はない）。
- ロックしている間に SSH から youtube-cli を使うと、「キーチェーンの確認ダイアログを出せません」で止まる。youtube-cli はコマンドのたびにキーチェーンから鍵を読むため。
- Mac の画面でもログインしていると、画面側のアプリもロックされる。次にキーチェーンを使うときにパスワードを求められる。

## うまくいかないとき

| 表示 | 原因と直し方 |
|---|---|
| キーチェーンの確認ダイアログを出せません | ロックが外れていない（手順 1）。外しても出るなら、今の youtube-cli にまだ「常に許可」を押していない。Mac の画面で `youtube-cli status` を実行して許可する |
| state が一致しません | 貼った URL が、今動いている `login` のものではない。`login` からやり直す |
| 時間切れです | 5分以内に貼り付けられなかった。`login` からやり直す |
| ブラウザでアクセスを拒まれる | そのアカウントがテストユーザーに入っていない（[setup.md](../setup.md)） |

- エラーの文面は `YOUTUBE_CLI_KEYRING=file` の指定を勧めるが、今の設定ディレクトリのまま付けてログインし直さない。キーチェーンの鍵とは別の `key` ができて、Mac の画面で普段どおり使ったときに鍵が食い違って止まる。どうしても Mac の画面で許可できないなら、`YOUTUBE_CLI_CONFIG_DIR` で別の設定ディレクトリにしたうえで使う（[headless.md](../headless.md)）。
- 「リモートログイン」のフルディスクアクセスは関係しない。キーチェーンはファイルを直接読むのではなく `securityd` を通して使うため。付けると SSH から保護された場所まで読めるようになるので、付けなくてよい。
